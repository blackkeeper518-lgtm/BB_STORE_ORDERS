
🛰️ 2. สายส่งเลขพัสดุและส่งแชทลูกค้า (Tracking & Messenger Pipeline)

ฟิวที่ใช้สับราง และ โชว์หน้าเวป สถานะนี้ สร้างจาก โฟร์ส่งเลขพัสดุ 👑BB_TRACKING คำนวนจาก ฟิว 
customer_message_time_th โดยใช้ ฟิวสัญญาณ = parcel_status_emoji เป็นตัวกระจายสัญญาณ 
กลับไปโต๊ะหลัก และโต๊ะต่างๆ เพื่อให้ view ในสายดึงข้อมูลได้ถูกต้อง โฟร์ส่งเป็นระบบ ลูกค้าทักปุ๊บ ส่งปั๊บ สถานะจะเปลี่ยนตามเวลา
ที่วนมาตามลอจิก รันทุกๆ 3 นาที

ฟิวสัญญาณ = parcel_status_emoji

🟢 = พร้อมส่ง
🟡 = เกิน 24 ช.ม.
🔴 = เกิน 48 ช.ม.
🔥SENT = ส่งแล้ว

🔮 หน้าที่ส่วนของสายส่งเลขพัสดุ

• table parcels: ตารางแกนกลาง ห้องที่มีเลขพัสดุที่เดียวในระบบ รองรับการอัปโหลดไฟล์ Raw Data มาจากขนส่ง ที่มีเลขพัสดุที่นี่ที่เดียว
• table 🧿BB_xXx_ORDERCONTROL: ห้องเก็บข้อมูลออเดอร์ที่จำเป็นทั้งหมด (เช่น ชื่อ, ข้อมูลลูกค้า) เพื่อใช้ทำบิลสำหรับห้องส่ง
• table page_tokens_vault: คลังแสงจัดเก็บโทเคนของแต่ละเพจ (Page Tokens) เพื่อใช้เรียกสิทธิ์ยิง API (โต๊ะนี้มีทุกโฟร์)
• view 🔮SHADOW_xXx_RECALL: วิวด่านแรก คอยดึงเฉพาะเลขพัสดุ ของลูกค้าที่มีรายชื่อใน 7 เพจ จาก table parcels
• view 🦅ROGUE_xXx_SHIPPINGz: วิวสายดึงข้อมูล ประกอบร่างเอาเลขจาก view 🔮SHADOW_xXx_RECALL มารวมกับข้อมูลบิลที่จำเป็นใน table 🧿 BB_xXx_ORDERCONTROL
• view ⛩️VOID_xXx_GATEWAYz: ประตูมิติ รวมข้อมูลจาก view 🦅 ROGUE_xXx_SHIPPINGz และดึงโทเคนเพจจาก table page_tokens_vault เข้ามาผสาน
• ระบบอัปเดตและดีดข้อมูลออก: เมื่อส่งเลขเข้าแชทเรียบร้อยแล้ว ระบบจะเขียนบันทึกกลับลงไปที่ table parcels โดยอัปเดตสถานะเป็น delivery_status = '🔥SENT' และลงเวลาในช่อง sent_at ทันที ส่งผลให้รายชื่อนั้น เด้งออกจากทุกวิวระบบงาน (Clear Queue)
• view 📓 DEAD_xXx_NOTE: "บันทึกมรณะสายส่งเลข" สถานีสุดท้ายที่เก็บ Log ประวัติการส่งเลขพัสดุหาลูกค้าที่เสร็จสิ้นภารกิจแล้วอย่างถาวร
